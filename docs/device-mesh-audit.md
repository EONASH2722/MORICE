# Device Mesh security and integration review

This is a separate post-implementation source review plus negative tests, not third-party penetration testing or certification. Scope: the mesh facade, typed protocol, TLS identity/trust, node admission, replay handling, Inbox, optional sources, Android additions and integration with Phases 1–4.

| Boundary | Review and observed protection | Remaining constraint |
|---|---|---|
| Pairing | Full certificate pin checked before the code; explicit confirmation on both devices; wrong code/pin, expiration, reused code and approval omission tested. Pair port cannot execute. | Out-of-band fingerprint correctness depends on user review; stolen OS account/private state is outside this boundary. |
| Normal transport | TLS 1.3, mutual certificates, exact pin, sender/response identity and trusted unrevoked peer. Plaintext and unknown certificates rejected. | No external cryptographic certification; Android Keystore/TLS interoperability needs a real device run. |
| Identity/storage | Existing P-256 identity, DPAPI on Windows, private Linux files, opaque Android key. Restart preserves the identity. Encrypted temporary SSL key files are removed. | No automatic five-year certificate renewal; Linux local-owner filesystem races are not a process sandbox. |
| Revocation | Trust state checked after TLS and at dispatch; contexts rebuilt; live RPC sockets closed; node work/source leases and queued actions cancelled; explicit re-pair tested. | Already completed external effects are not rolled back. A noncooperative native source may require owner intervention. |
| Frames/messages | Bounded frame/depth/strings/arrays/properties, strict duplicate keys, finite numbers, typed IDs/capabilities/operations. Authenticated invalid frames leave the node usable. | Bounded denial of service by an authorized peer remains possible; no WAN service exposure is recommended by this implementation. |
| Admission | Eight RPC slots/backlog, short timeouts, per-IP/global rate bounds, four command driver slots, existing resource reservations before drivers, bounded command/queue/source counts. | Routing health/capacity is advisory; another coordinator may win the physical node lease and produce a busy result. |
| Permissions | Existing central controller, paired inbound/outbound capability grants, per-node state, exact action-bound one-use confirmation, deny/OS-required preservation, withdrawal hides old output, session reset. | Source-picker workflows still obey existing global file-read policy; the mesh does not create blanket filesystem authorization. |
| Replay/recovery | Peer-owned stable IDs plus input/expected-state digests; mutation intent persisted before execution; no automatic replay after disconnect/restart; original intent can be observed independently. | Durable mutation ledger deliberately fails closed when bounded history fills. No automatic mutation-history deletion is safe. |
| Evidence | Network ACK cannot pass verification. Existing node Kernel proof plus fresh Phase 3 observation, concrete desired state and false-success tests. File size/hash is checked locally. | A paired malicious node controls its own observations. This is device authorization, not remote attestation of an uncompromised OS. |
| Inbox | Same existing path/secret guard, UUID peer ownership, bounded chunks/records/leases, actual resume readback, SHA-256 + size, no-overwrite publish, corrupt/traversal/different-target tests. | Python max 1 GiB, Android max 64 MiB; not general remote filesystem access. Persisted partial expiry is sensitive to clock rollback. |
| Source streams | Explicit local factory, real permission + exact start confirmations, shared persistent leases, owner checks, bounds and hash checks. Withdraw/disable/revoke cancel owned sessions even after start completes; expiry detects OS permission/source withdrawal. | Synthetic test source only. Unreachable peers cannot confirm immediate cleanup; inactivity is 30 seconds and lifetime at most 60 seconds. Native source reads/close must cooperate. |
| Shell/projects | Shell/install absent from default exposure. Source inspection does not extract/run; reviewed builder binding delegates to the existing authority and checks current source/artifacts. | Existing command gates do not isolate hostile project/package code; no remote installer or unrestricted terminal supplied. |
| Redaction/injection | Audit stores IDs/capability/state only. Existing action journal omits raw data/audio/frame/private key/code fields. Remote event whitelist rejects policy-bearing messages. | Friendly names and file names are still displayed as user data; device metadata cannot become instructions. |
| Lifecycle/UI | Lazy disabled startup, actual empty Devices panel, supported file action visibility, explicit pairing identity review, bounded background UI operation, active-operation close guard. | LAN interfaces/OEM services can drop; no cloud relay or unbounded background polling. |

Corrections made during this review:

- Added pre-worker physical-node resource reservation; resource contention no longer enters a waiting command driver.
- Prevented large range-idempotent file transfers and sampled/read-only operations from filling durable mutation history. Mutation IDs retain fail-closed replay protection.
- Rejected boolean chunk offsets, invalid resource claim types, dangerous advertised validation patterns and mistyped health values.
- Restored source checkpoint probes to the original node instead of dispatching locally.
- Bound one-use actions to the exact task/input, reset session policies on disconnect/disable/revoke, and hid completed private results after permission withdrawal.
- Made admission persistence failures release slots/leases, and unexpected execution failures become uncertain rather than replayable success.
- Made interrupted intent reconciliation compare the original digest/desired state with a fresh observer, without invoking its handler.
- Required observed fields to exist even when a requested value is null; an absent observation cannot become verified.
- Made duplicate named chat targets require a unique selection and rendered pairing/status text as plain text.
- Registered inbound approved peers for Devices/heartbeat reconnect; renaming never changes cryptographic identity.
- Loaded/expired owned persisted partial metadata after restart; synchronized source/partial expiry with concurrent operations.
- Kept network disable effective when native source cleanup reports an unconfirmed close, retaining the physical capture lease.
- Made permission withdrawal deny before cleanup and cancel owned remote sources even after their start command completed. Disable shares a two-second cancellation budget before closing networking; stream tests cover local denial, OS permission withdrawal and mesh disable.
- Android now rejects bounded malformed JSON, verifies actual volume, includes desired state in idempotency digests, bounds its worker queue/rate, prunes only safe operations and closes active service sockets.
- Added Android's normal audio-settings and connected-device network prerequisites. Fresh Android observations downgrade stale volume/file success; compilation is not device execution evidence. See the [connected-device requirements](https://developer.android.com/develop/background-work/services/fgs/service-types#connected-device) and [audio permission](https://developer.android.com/reference/android/Manifest.permission#MODIFY_AUDIO_SETTINGS).
- An existing GUI integration test's eight-second wait expired under host load and raced workspace cleanup. Its bounded completion wait is now 30 seconds; file/content/completion assertions remain intact.

Negative evidence includes wrong/expired pairing, unapproved trust, invalid pins, plaintext/unknown TLS, revoke/re-pair, denied/exact/session policies, forged schema/routing metadata, impossible resource requests, no-op mutation, absent desired state, drop/reconciliation, duplicate conflicts, durable interruption, cancellation, partial/resumed/corrupt files, traversal, unsupported source permission, stream cleanup, injected events, frame/version/ID/depth bounds and queue cancellation. The fixture uses actual localhost TLS and actual Kernel execution. It does not simulate network ACK as final success.

Android debug/instrumentation builds succeeded. Three new Android instrumented cases are compiled but unexecuted: stable non-exportable identity, strict malformed frames and private Inbox hash/traversal behavior. No physical device is attached. The task-owned emulator failed with a missing hypervisor driver; software emulation stayed offline and was stopped. No driver was installed. Linux/WSL/SBC execution is unavailable. These are deployment-validation gaps, not passing hardware tests.

The old v1 pairing API remains compatibility-only, with desktop network startup off and Android fallback loopback-only. Its historical unprotected pairing exchange must not be represented as mesh security. Provider constraints from Phases 3–4 remain: incomplete universal semantic vision/UIA, external-browser/frame coverage, uncooperative native providers and hostile-code sandboxing. No Phase 6–9 features or public release actions were added.
