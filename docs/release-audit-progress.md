## Current findings

`docs/release-audit-issues.json` is the issue ledger. Acceptance gaps are distinguished from reproduced implementation defects. In particular, production still constructs the legacy window, the complete feature parity matrix is pending, final paint/load/soak acceptance is pending, and no wheel/frozen candidate matches the current source.

The latest visual steering requests a clearer interface, stronger cursor design and exclusively authored UI pictograms. Phase 10 now has 61 hand-drawn vector marks, grouped navigation, a compact adaptive composer, simpler Appearance with searchable advanced fields, local bounded cursor lighting and explicit Reduced Motion settling. The original MORICE logo was not edited. These refinements have focused native evidence, not a final release declaration.

A genuine runtime problem surfaced during the new Media access checks: `MediaLab.status()` scanned `PATH` for FFmpeg and FFprobe on every poll. The actual thread trace shows an interactive worker inside `shutil.which` / `_access_check`. A slow path entry prevented ordinary status requests from settling. The existing MediaLab now retains explicitly labelled encoder diagnostics, initially `NOT_CHECKED`; regular status reads do not probe tools. Explicit resource refresh uses the existing background executor and updates that cache. Generation/export verification and the existing permission controller remain authoritative. An explicit path probe can still depend on filesystem responsiveness; it is no longer periodic interactive work.

Media export also referenced a nonexistent `ExecutionResult.message` and then compared the verification enum with the wrong uppercase string. Its callback now uses the actual `VerificationStatus.VERIFIED` contract and reports real execution errors. The controlled PNG export test exercises the actual Kernel export, readback/hash and DENIED behavior. Its initial fixture wrongly assumed that a selected filename grants default ASK permission; the fixture now supplies GRANTED only to the owned test controller and restores it. Production never automatically changes that permission.

Native pointer testing uses controlled events delivered to owned Qt widgets, with actual native rendering. It is not physical input or an arbitrary desktop automation claim. Two exploratory QTest mouse moves did not establish pointer delivery; their failure logs are retained. The corrected evidence explicitly records the event source and bounded settling time.
