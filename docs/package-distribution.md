# Package Distribution

MORICE 0.8.0 is built from one source revision and one authoritative version in
`morice/version.py`. The release pipeline stops if tests, type checking, package integrity,
version consistency, secret scanning, archive policy, split-part hashes, or final checksums fail.

## Published Channels

| Channel | Release status | Installation |
| --- | --- | --- |
| [GitHub Release installer](https://github.com/EONASH2722/MORICE/releases/tag/v0.8.0) | Published | Setup executable plus all adjacent `.bin` slices |
| [GitHub Release portable](https://github.com/EONASH2722/MORICE/releases/tag/v0.8.0-portable) | Published | Reassemble verified parts, extract, run `MORICE.exe` |
| [Android companion APK](https://github.com/EONASH2722/MORICE/releases/tag/v0.8.0-android) | Published | Install the signed Android 9+ APK after checking its adjacent SHA-256 manifest |
| Python wheel and sdist | Built and verified locally | Install the downloaded wheel; no public index claimed |
| PyPI | Not published | Requires verified project ownership and a PyPI token |
| GitHub Packages | Not applicable to Python wheels | GitHub Packages does not provide a PyPI-compatible registry |
| WinGet | Not submitted | The model-bundled disk-spanning installer is not a single downloadable installer |
| Chocolatey | Not submitted | Publisher account and package moderation are required |
| Scoop | Not submitted | A public bucket and stable release URLs are required |

The README only shows commands that work with artifacts generated by this repository. Public
package-manager commands must be added only after the corresponding listing is accepted.

## Python Package

Package name: `morice-ai`

```powershell
python -m pip install .\morice_ai-0.8.0-py3-none-any.whl
morice
```

Upgrade and removal:

```powershell
python -m pip install --upgrade .\morice_ai-0.8.0-py3-none-any.whl
python -m pip uninstall morice-ai
```

The wheel contains MORICE Python modules, UI assets, and console metadata. It intentionally does
not contain the 4.7 GB GGUF, llama runtime binaries, caches, tests, logs, private configuration,
or developer workspace files. Select a compatible local GGUF or Ollama model after launch.

## Build

Install development tooling and run the verified pipeline:

```powershell
python -m pip install ".[dev]"
powershell -ExecutionPolicy Bypass -File scripts\build-release.ps1
```

Generated release metadata includes:

- `SHA256SUMS.txt` and `checksums.json`;
- a split-asset manifest with per-part and combined hashes;
- `MORICE-v0.8.0-Package-Contents.json` with archive inventory and policy results;
- versioned release notes, documentation, source archive, wheel, and sdist.

The Android companion is published separately as `v0.8.0-android`. The portable plug-and-play
bundle is published as `v0.8.0-portable` so its split parts and reassembly script remain together.
Both tags point to the same audited `0.8.0` source revision; they are distribution variants, not
different application versions.

## Signing

The Windows binaries are unsigned because no trusted Windows Authenticode certificate is
configured. The pipeline never creates a fake signature. A future signed Windows release must
validate the Authenticode chain before publication.

The Android APK uses a dedicated 4096-bit RSA release key stored outside the repository and is
verified with Android `apksigner`. Its adjacent JSON manifest records the final APK hash. This is
application signing for upgrade identity and package integrity; it is not a claim of Play Store
publication or third-party publisher certification.
