# Phase 9 independent audit

Audit date: 6 October 2026. This is a fresh manual review of the final implementation and its evidence, supported by `scripts/audit_phase9_media.py`. It was performed by the implementing agent; it is not an external security certification or a review by a second person. Completion evidence is recorded separately by `scripts/verify_phase9_completion.py` after package validation.

## Reviewed boundaries

The review traced requests from `RuntimeServices.media` through capability registration, admission, permission checking, shared resource reservation, backend execution, independent decode/hash verification, publication, Kernel completion and history. It also reviewed cancellation, restart, native GPU vision, idle LLM release, Builder, Research, Mesh and Ambient integration. Searches covered subprocesses, heavy imports, custom model execution, waits, recursive cleanup, successful-state assignments and retained leases.

The final tree contains 182 Python modules, including 16 Media Lab modules. All parse successfully. No Media Lab module imports Torch, Diffusers, Transformers or Accelerate at module scope. Both the desktop and separate media environment pass `pip check`. `build/phase9-final-audit.json` records the source fingerprint and dependency receipts. These mechanical checks support the review; they do not prove general security by themselves.

## Failure and recovery evidence

The final targeted selection has 48 passing cases; the final complete MORICE suite has 923 passing tests and 62 passing subtests. Earlier failures remain in their original logs and are not counted as passing runs. `build/phase9-post-audit-full-tests.log` is the final regression receipt.

`build/phase9-safety-soak.json` records a real Torch CUDA allocator OutOfMemoryError in an isolated owned process: the worker has a 64 MiB allocator allowance and attempts 128 MiB. It does not load diffusion weights or exhaust host VRAM. MORICE survives, records failure without artifacts, reaps the worker, and completes 15 subsequent controlled Pillow image jobs in an actual offscreen `MoriceWindow`. The result has clean shutdown, zero pending workers and zero leases. This validates the CUDA exception boundary and subsequent shared-runtime recovery; it does not demonstrate diffusion-model OOM recovery.

Controlled subprocess tests additionally cover hard exit, corrupt/constant/wrong-size files, cancellation, one explicitly authorized smaller OOM retry, resource waits, queue bounds, permission denial, retained cleanup, interrupted restart and profile invalidation. A failed attempt never supplies a successful artifact. The complete real outpaint/MAXIMUM_THAT_FITS suite did not finish, and the original suite cannot claim final clean shutdown.

## Remaining concrete constraints

- The remaining SD-Turbo checks need approximately 5.7 GiB free RAM under the conservative planner; observed available RAM fell to roughly 3.6–3.9 GiB. The user chose to keep this constraint documented. Real offload, actual GGUF/media contention, diffusion-model OOM/recovery, actual-model cancellation, successful outpaint Kernel commit and fresh MAXIMUM_THAT_FITS replay remain unvalidated. Separate real image generation, image edits and five benchmark images have already succeeded.
- The unexpected original native suite parent exit has no established cause. A fresh 16-case lightweight native UI safety/soak run passes. This narrows the validated scope but does not establish long-term stability for repeated diffusion loads under memory pressure.
- No approved video model or motion weights, live ComfyUI setup, or ffmpeg/ffprobe installation exists. Optional adapter/verification contracts are tested with fixtures. Video and image-to-video are explicitly unavailable locally.
- Supported diffusion classes are a reviewed finite set. Other architectures, quantization, LoRA/control nodes, independent neural upscaling and background removal require additional provider work and real validation. Metadata is not a compatibility guarantee.
- Process telemetry depends on psutil. Absent/inaccessible process identity causes conservative quarantine or unconfirmed cleanup; it does not provide OS process isolation. Foreign allocations can change between samples. Direct/native calls and backend health probes are bounded but cannot guarantee instant interruption.
- ComfyUI progress is an observed submitted/generating stage, not step progress; its API fixture does not prove all upstream versions or physical allocator release. An API request can run up to its configured timeout, and model-release confirmation is deliberately conservative.
- Startup/idle samples are short and load-sensitive. Initial package/build timing spanned machine suspension and is not a normal latency measurement. A finite soak is not a lifetime leak or reliability guarantee.
- Completed outputs and user model weights are never automatically deleted. History and derived caches are bounded; outputs, benchmark evidence and quarantined files need an explicit retention policy. The older rejected-cleanup temp folder is retained as a known exception.
- No embedded content classifier exists in this SD-Turbo bundle. Metadata exposes that fact; decoded-file verification is not a safety/content or scientific-validity classifier. Backend refusals remain failures. Model licensing is retained with the pinned bundle and must be checked for the intended use.
- Packaging validates a local Windows build, not signing, an installer upgrade, macOS/Linux, physical Android, or cloud deployment. Production OAuth/relay/voice and broad external desktop/site compatibility retain their earlier documented limits.

Phase 10 may consume the stable schema-1 APIs for the validated local image scope. Its interface must preserve unavailable/degraded states, conservative admission, explicit constraints and truthful failure/recovery. It must not present optional unvalidated workflows as tested providers.
