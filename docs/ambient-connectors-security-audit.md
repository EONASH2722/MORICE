# Phase 7 source, security and privacy audit

This is a separate review pass by the implementing agent, not a claim of independent third-party certification. The review considered denied, malformed, replayed, interrupted and concurrently changing inputs as well as successful controlled workflows.

## Architectural review

Inspected the existing kernel execution, registry, permission, resource, event and telemetry code; coordinator, WorkerManager and SharedTaskState; VerifiedActionRuntime bindings/journal; AutomationEngine and NotificationManager; SecureVault; Builder completion; Research ingestion/experiment persistence; and Mesh authenticated dispatch. Phase 7 composes those authorities. The nine roles remain. Worker context gains only bounded causality references in its existing allowlist. The coordinator already retains at most 20 completed graphs and forgets corresponding worker/shared-state records. No duplicate runtime or private connector execution authority was introduced.

## Security review

- Account connection requires an explicit device authorization action and the existing granted network permission. ASK/DENIED network states are tested to prevent even the initial account request. Bearer/refresh/webhook credentials use the existing Windows DPAPI vault. Device codes remain transient. Assignment notices use an observed `/user` identity rather than any assignment in a repository.
- Connector descriptors must advertise implemented operations and cannot collide with existing capability namespaces. Read, write and auth scopes use the shared permission controller. Writes require the exact existing one-use approval and independently retrieved object state. HTTP acknowledgments cannot establish the effect.
- Origins are official HTTPS addresses, redirects are disabled and loopback HTTP is restricted to explicit fixtures. Response bytes, request bytes and socket deadlines are bounded. Cancellation remains the existing linked kernel token. OS DNS resolver latency is an explicit remaining constraint.
- Signed webhooks are verified before content processing. Body-hash dedupe prevents changing an unsigned delivery header from replaying an action. The persistent 1,024-body ledger fails closed until explicit secret rotation. The receiver uses one request thread, bounded backlog, body limits and a total request watchdog; no public port/tunnel is opened.
- Event bodies cannot carry passwords, tokens, cookies, prompts or nested private content. Watches cannot store nested secret/approval fields, dynamically select file scopes, elevate external mutations to reversible actions, or grant authority through event text. Derived causal keys/depth remain references rather than commands or permissions.
- Quarantine refuses links/reparse paths/multiple hard links, locks a native file handle against writes/deletes, preserves an encrypted copy and intent before removing the exact file by handle. Restore uses exclusive creation and canonical handle identity, refuses overwrite and independently verifies bytes. Denied, changed-hash and changed-process-identity requests do not mutate the target.
- Termination retains the exact PID/executable/start-time process handle through exit observation. MORICE and core Windows executables are excluded. Verified containment records an incident action and timeline. No automatic termination/quarantine, offensive tools or broad firewall manipulation was found.

The review found and corrected: enum-only health results violating the existing registry contract; header-based webhook replay keys; lock inversion between event delivery and dispatch; a missing worker causality allowlist entry; an incident-history slice error; repeated notification risk after a partially committed tick; whole-directory enumeration before the file-count cap; and race-prone path-based evidence deletion/restore. A deterministic concurrency test also reproduced two confirmations claiming one pending consequence: the durable receipt now transitions atomically from awaiting confirmation to running before any provider effect, so only one exact approval can dispatch it. Adversarial tests were added for those behaviors rather than treating a happy-path HTTP fixture as complete validation. Full-suite test ordering also exposed a test synchronization race: the durable experiment checkpoint precedes completion-event publication. The integration test now waits for the actual verified notification receipt with a bounded deadline, rather than assuming both observations occur simultaneously.

## Privacy review

Ambient SQLite stores configuration, public references, decision receipts, causal keys and cursors. It excludes private provider message bodies and credentials. Kernel lifecycle logs retain ids/status/timings; secrets do not enter kernel arguments or error text. Connector HTTP exceptions are converted to bounded generic diagnostics. Temporary provider read bodies stay in the existing bounded in-memory workflow history and are labeled untrusted; they cannot become permission instructions.

Security collection is off until explicitly configured, limited to local metadata and selected directories/PIDs. No new screen, camera, microphone, clipboard or background audio capture exists. Finding evidence is path/hash/start identity or small selected metadata, not bulk file contents. Quarantine bytes use DPAPI; restoration requires another exact approval. Selected Research imports remain subject to the earlier project's explicit file-read and provenance rules and are not covert ambient captures.

The panel does not display tokens or claim a machine is safe. Monitoring off, collector failures, pending exact confirmations, dropped-event counts and provider state are visible. No external messages, real account changes, uploads, pushes, tags, release actions or public deployments were performed.

## Evidence and limits

The three Phase 7 behavior/audit modules exercise actual loopback HTTP reads/writes, signed HTTP delivery, DPAPI rotation, durable restart, false-positive suppression, real owned Windows process termination, encrypted quarantine and hash-preserving restore. Cross-phase tests execute a genuine paired TLS remote capability, approved local Builder repair and real Research source/experiment updates. The separate fast-path module uses the existing controlled native-window adapter to test “Open Calculator” under a 10,000-event backlog; it does not claim a physical application launch.

Final source regression passed 844 tests and 59 subtests; the ordered integration/authority review passed 64 tests. Performance measurements, startup and package source parity are recorded in `ambient-connectors-security-report.md`; reproducible outputs are under `build/phase7-*`. The source wheel is verified independently from the editable checkout, with parity for 90 runtime modules and an actual isolated wheel smoke. Frozen Windows releases and physical Android/Linux devices are not validated by this phase. A registered live GitHub app, external HTTPS relay and real account consent were not available or assumed. Other connector families, rich process/signature/persistence analysis, remote security telemetry, semantic event models and broad network isolation remain explicitly unsupported. These are technical extension constraints, not fabricated active capabilities.
